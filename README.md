# image-wise

A TensorFlow notebook for binary image classification with a custom convolutional neural network. The experiment uses folders labeled `happy` and `sad`, trains on resized RGB images, and includes learning curves, test metrics, single-image inference, and model serialization. These labels describe the dataset classes; the model does not establish a person's emotional state.

## Model and workflow

Images are loaded with `image_dataset_from_directory`, using its default 256 × 256 RGB input size and batch size of 32. Pixel values are divided by 255 before training.

| Stage | Configuration |
| --- | --- |
| Convolution blocks | Three 3 × 3 Conv2D layers with 16, 32, and 16 filters, each followed by max pooling |
| Hidden layer | Flatten followed by 256 ReLU units |
| Output | One sigmoid unit; threshold 0.5 for binary classification |
| Optimization | Adam with binary cross-entropy, trained for 20 epochs |
| Reporting | Training/validation loss and accuracy; test precision, recall, and binary accuracy |
| Export | `models/image-wise.h5`, reloaded for a second prediction |

The network is trained from scratch. No pretrained backbone, augmentation, dropout, or early stopping is configured.

## Run locally

Use **Python 3.11** for the existing `imghdr` import. Dependencies are unpinned; no version lock is provided.

```bash
git clone https://github.com/quixoticalcoder/image-wise.git
cd image-wise
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyterlab
```

On Windows, activate with `.venv\Scripts\activate`. Launch Jupyter from the repository root and run `ImageClassifier.ipynb` in order using the environment's Python kernel.

Supply your own appropriately licensed images in this layout:

```text
data/
├── happy/
│   └── ...
└── sad/
    └── ...
examples/
└── sample.jpg
```

Folder names determine the inferred class order. The printed prediction labels assume `happy = 0` and `sad = 1`; keep that folder order or update the labels. The data directory should contain only class directories. Training images and the example inference image are not included.

**Use a working copy of your dataset:** the notebook's format-cleaning cell deletes files whose detected format is outside its JPEG/PNG/BMP allowlist. It does not reliably reject every unreadable image because the OpenCV decode result is not checked.

The notebook creates the model directory during export and writes TensorBoard logs to `logs/`. To inspect them:

```bash
python -m tensorboard.main --logdir logs
```

Generated datasets, logs, model files, and the local sample image are ignored by Git. Existing embedded figures are preserved as historical outputs and can be regenerated by rerunning the notebook.

## Implementation boundaries

- **Partitioning:** the notebook takes and skips batches from a shuffled dataset to approximate 70/20/10 partitions. Separate iterations can reshuffle membership, so train, validation, and test observations are not guaranteed to remain disjoint. The added batches and integer rounding can also leave the test partition smaller than requested or empty for small datasets.
- **Inference preprocessing:** OpenCV reads the sample image in BGR order. The display converts it to RGB, but the prediction path resizes the original BGR image. This differs from the RGB training input and should be corrected before relying on sample predictions.
- **Reproducibility and evidence:** dataset shuffling and model initialization are not seeded. No dataset provenance, independent benchmark, subgroup analysis, or reproducible performance result is provided.
- **Deployment:** this repository contains one experimental notebook, rather than an application or serving API. Training data and a saved model must be supplied or generated locally.

Resolve partitioning and preprocessing consistency before interpreting the reported metrics as held-out performance.
